19. 3D ENGINEERING SPECIFICATION
Initialize renderer with antialias if performance permits, alpha if necessary, and appropriate power preference, but gracefully handle WebGL initialization exceptions. Use correct output color space and tone mapping appropriate to the installed Three.js version; verify rendering. Do not mix deprecated Three.js API patterns from outdated tutorials. Ensure scene scale, lights, geometry and materials have predictable ownership. Centralize object disposal: geometries, materials, textures, render targets, passes, animation loops, event listeners, GSAP timelines, and observer handles. On Vue unmount or hot reload, release resources, kill triggers, remove ticking listeners, and call dispose on renderer/context where appropriate. Avoid memory leaks when navigating or resizing.

Use procedural geometry where it provides meaning: neural node graph (InstancedMesh spheres with edges), a tubular ribbon spline, task scheduler capsule instances, connected lanes, pipeline slabs, checkpoint cubes, and a minimal scene halo. You can write authored ShaderMaterial for subtle signal movement, but supply robust compile fallback and prefer Three.js standard materials where quality is comparable. No externally hosted GLB model should be mandatory. If a custom GLB is generated offline and included, use compressed glTF when available, and provide source/credit; do not require Blender on the deployment server. Keep file sizes sane. If geometry is intricate, create reusable helper functions such as createRoundedSlab, makeCircuitTrace, createNodeNetwork, and createTaskCapsule.

Avoid per-frame material allocation, BufferGeometry rebuilds for static elements, expensive shadow map updates, too many transparent overlapping meshes, depth sorting artifacts, huge postprocessing multipass chains, and running multiple render loops. Circuits can be authored with thin tube segments and instanced motifs. Render lines with stable WebGL-compatible thickness techniques: be cautious because native LineBasicMaterial linewidth is effectively limited in WebGL; use appropriate meshes or supported addons if thick lines are essential. For translucent cards, composite lightly with HTML rather than huge glass physical materials. Use fog to create depth sparingly; gradients and background planes often achieve the effect with much lower cost.

Performance tiering should be explicit: Tier A desktop high capability supports the full sculpture, subtle bloom, mid particle count, detailed GPU stack; Tier B normal laptop disables heavy postprocessing and lowers geometric detail; Tier C mid-range mobile uses simplified materials, static or lightly animated 3D, fewer particles and at most one simple animated focal object; Tier D reduced motion/WebGL unavailable shows carefully authored 2D compositions with all content and working links. Detect features, respect prefers-reduced-motion and prefers-reduced-data where available, and avoid making a performance assumption based only on screen width. A capable phone and an overloaded laptop should be handled sensibly.

Potential budgets (targets, not invented measured results): background node instances approximately 80–180 desktop, 20–60 mobile; concurrent draw calls ideally under about 100–150 for the active hero scene and fewer on mobile; pixel ratio cap 1.5–1.75 desktop and 1.0–1.25 mobile depending on profiling; one renderer context; no unnecessary continuous animation while fully offscreen or hidden. These are adjustable engineering guidance, not claims of achieved performance.

Use ResizeObserver or appropriate resize events to update viewport, renderer display resolution, camera projection and ScrollTrigger.refresh after fonts/images become stable. Read the Three.js official responsive rendering guide before blindly setting devicePixelRatio: https://threejs.org/manual/pages/responsive.html . Choose actual drawing resolution with performance in mind. On high-DPR mobile, do not render at 3x native by default. Pause renderer on document visibility hidden. If power-saving mode cannot be detected reliably, default to sensible baseline.

36. FRAME COORDINATION REFERENCE IMPLEMENTATION
Implement a single authoritative update loop. One robust approach is to synchronize Lenis and ScrollTrigger using the official Lenis recipe: create one Lenis instance with RAF driven externally, listen to lenis scroll events to invoke ScrollTrigger.update, and run lenis.raf(timestampMilliseconds) from a GSAP ticker callback; disable ticker lag smoothing if the integration requires it. Feed active scene progress from ScrollTrigger into a small mutable controller. Advance scene animations and renderer with the same clock where feasible. Do not simultaneously set Lenis autoRaf=true AND add a second manual RAF loop to it. Use Vue mount/unmount hooks and clean up the ticker listener on unmount. Respect reduced motion by not initializing smooth scrolling or using native behavior.

Examples of technical correctness to verify rather than blindly paste:
- GSAP ticker passes time in seconds; Lenis raf expects milliseconds in the documented integration.
- Resize should call renderer resize, camera projection update, and ScrollTrigger.refresh after layout has stabilized.
- ScrollTrigger matchMedia can create different chapter timelines for desktop vs mobile.
- Pinning an element inside a transformed ancestor can cause unexpected fixed-position behavior; avoid nested pin fights.
- On reload at a deep hash, the correct 3D state should be reconstructed deterministically.
- Recreating a full scene on every reactive state update is a severe bug.
- Transparent geometries may sort incorrectly; reduce overlapping transparent materials and configure depth behavior thoughtfully.
- A canvas overlay needs pointer-events none unless a specific interaction is being actively handled; project links must remain clickable.
- Three.js dispose must clean GPU objects; Vue's removal of the canvas alone is not enough.
- Global event listeners and gsap triggers must be killed on unmount; hot module reloading should not multiply them.
